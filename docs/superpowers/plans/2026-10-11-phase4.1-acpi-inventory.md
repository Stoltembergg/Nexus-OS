# Phase 4.1 ACPI Inventory Implementation Plan

> **Execution status:** Completed 2026-10-11; see `docs/16-phase4.1-acpi-inventory-evidence.md` for validation evidence and limitations.
> **For agentic workers:** REQUIRED SUB-SKILL: `executing-plans`. Implement this plan with review checkpoints; do not begin Phase 4.2.

**Goal:** Discover and validate the firmware RSDP/root/MADT and report bounded LAPIC, processor, IOAPIC, and interrupt-override metadata while interrupts remain disabled.

**Architecture:** The UEFI loader locates the RSDP from `EFI_SYSTEM_TABLE.ConfigurationTable` and passes its physical address through the existing `BootHandoverInfo.rsdp_address`. After the kernel establishes its identity map, a bounded physical reader validates ACPI memory ranges before calling an alignment-independent, host-testable parser. QEMU/OVMF evidence proves the real firmware inventory path; independent generated fixtures prove malformed-input rejection.

**Tech Stack:** `no_std` Rust UEFI loader/kernel, Rust unit tests, Python fixture generator, existing QEMU/OVMF hardening harness.

**Spec:** `docs/superpowers/specs/2026-10-11-phase4.1-acpi-design.md`

## Global Constraints

- Implement only Phase 4.1; do not initialize or access APIC MMIO registers, enable IF, modify CR8/IDT/IRQL, add IRQ handlers, timers, preemption, threads, or SMP.
- Prefer ACPI 2.0 RSDP; fall back to ACPI 1.0 only when the ACPI 2.0 configuration-table entry is absent.
- Do not require 16-byte alignment for the RSDP target supplied through UEFI `VendorTable`; that rule applies to legacy IA-PC memory scanning, which this implementation does not use. Keep alignment checks on the EFI configuration-table array itself and all physical range/mapping checks.
- Reject malformed advertised tables and invalid physical ranges before dereferencing; absent ACPI is a distinct unavailable result.
- RSDP extended length is 36 bytes through 4 KiB; maximum SDT length is 1 MiB. These are defensive kernel bounds, not ACPI normative maxima.
- ACPI table bytes must be covered by `AcpiReclaimMemory` or `AcpiMemoryNvs`, below the current 4 GiB physical-map ceiling, and identity-mapped. APIC MMIO bases are validated as addresses but never dereferenced.
- Fixed inventory capacities: 256 processors, 16 IOAPICs, and 256 interrupt overrides; reject overflow, do not truncate.
- Do not add dependencies or modify the pre-existing untracked `docs/15-phase4-verifiable-deliveries.md`.
- Existing exception behavior and every Phase 0–3.7 test/gate must stay green. QEMU/OVMF evidence is not physical-hardware evidence.

**Interface:**

```rust

    entries: &[EfiConfigurationTable],
```

`EfiConfigurationTable` is `#[repr(C)]` with `vendor_guid: EfiGuid` and `vendor_table: *const c_void`.

`None` means no ACPI GUID is present. A present preferred ACPI 2.0 entry with a null table pointer is malformed and must not be hidden by falling back. ACPI 1.0 is used only if ACPI 2.0 is absent.

## Task 3: implement the pure ACPI decoder with negative tests

**Files:** `crates/nexus-kernel/src/arch/x86_64/acpi.rs`, generated fixture files from Task 2.

**Interfaces:**

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) enum AcpiError {
    PhysicalRange,
    Signature,
    Checksum,
    Length,
    Entry,
    Capacity,
    MissingMadt,
}

pub(crate) trait AcpiPhysicalReader {
    fn read_phys<'a>(&'a self, address: u64, length: usize) -> Result<&'a [u8], AcpiError>;
}

pub(crate) fn parse_inventory<R: AcpiPhysicalReader>(
    reader: &R,
    rsdp_address: u64,
) -> Result<AcpiInventory, AcpiError>;
```

`AcpiInventory` derives `Debug` and `Clone` and stores RSDP revision and RSDT/XSDT/MADT addresses; the effective Local APIC base; a fixed array of 256 processor records (`apic_id`, firmware UID, enabled/online-capable flags, x2APIC discriminator); 16 IOAPIC records (`id`, physical base, GSI base); and 256 source overrides (`bus`, source IRQ, GSI, polarity, trigger), each paired with a count.

- [x] Add tests that load the generated valid RSDT and XSDT images through a mock `AcpiPhysicalReader`; assert the expected APIC IDs, LAPIC base, IOAPIC, and override fields. Also parse the valid unaligned RSDP from address `0x100014`:

```rust

    base: 0x10_0000,
    bytes: include_bytes!("../../../../../tests/fixtures/acpi/valid_xsdt.bin"),
    denied: None,
};
let inventory = parse_inventory(&reader, 0x10_0000).unwrap();
assert_eq!(inventory.lapic_address, 0xfee0_0000);
assert_eq!(inventory.processors[0].apic_id, 0);
assert_eq!(inventory.io_apics[0].address, 0xfec0_0000);
assert_eq!(inventory.overrides[0].gsi, 2);
let unaligned = FixtureReader {
    base: 0x10_0000,
    bytes: include_bytes!("../../../../../tests/fixtures/acpi/valid_unaligned_rsdp.bin"),
    denied: None,
};
assert!(parse_inventory(&unaligned, 0x10_0014).is_ok());
```
