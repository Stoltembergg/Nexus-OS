# Nexus OS — Phase 4.1 ACPI inventory design

**Status:** approved design, updated after QEMU/OVMF validation of the UEFI RSDP pointer.

## Goal and scope

Discover and validate the firmware ACPI root and MADT so the kernel can report the Local APIC base, processor APIC identifiers, I/O APICs, and interrupt source overrides. This is an inventory only: do not map or access APIC MMIO registers, program either APIC, alter CR8/IDT/IRQL behavior, enable interrupts, or add timers, scheduling, preemption, or SMP.

Keep the existing boot handover field `BootHandoverInfo.rsdp_address`. During UEFI boot, locate the RSDP via `EFI_SYSTEM_TABLE.ConfigurationTable`, preferring the ACPI 2.0 GUID and falling back to ACPI 1.0. Bound the configuration-table count (256 entries), validate the configuration-table array's alignment and checked byte-size/address arithmetic, then pass the selected RSDP physical address unchanged. Do **not** require the pointed-to UEFI RSDP to be 16-byte aligned: ACPI 6.6 §5.2.5.1's 16-byte rule is for legacy IA-PC memory scanning; §5.2.5.2 obtains the RSDP through the UEFI pointer. Read its fields byte-wise. After `mem::init_memory`, the kernel ACPI discovery code validates and reads physical table ranges through the current identity map. Before dereferencing, confirm each complete range is covered by `AcpiReclaimMemory` or `AcpiMemoryNvs`, lies below the current 4 GiB physical-map ceiling, and is actually identity-mapped. Reject unsupported table addresses/ranges before access rather than expanding the mapper in this phase.

## Parsing and fail-closed rules

Use an alignment-independent little-endian byte parser, separated from unsafe physical reads so malformed-input tests can run on the host. Validate the UEFI-provided RSDP signature without imposing a 16-byte alignment rule, its v1 checksum, and for revision 2+ an extended length of at least 36 bytes and at most 4 KiB plus its full-length checksum. Validate root signature, bounded length, checksum, entry-width divisibility, checked address arithmetic, and every candidate table range before probing it. Enforce a 1 MiB maximum SDT length as a defensive kernel policy, not an ACPI normative limit. Require exactly one valid MADT; reject duplicate MADTs and malformed supported records.

Validate the MADT fixed header and checksum, then walk entries using checked cursor arithmetic. Check every entry has a complete type/length prefix and fits in the remaining table. Validate minimum structure sizes for recognized MADT records; collect processor Local APIC records (type 0), I/O APIC records (type 1), Interrupt Source Overrides (type 2), Local APIC Address Override (type 5), and x2APIC processor records (type 9). Skip unrecognized records only after their generic bounds are valid. Bound collected records to 256 processors, 16 I/O APICs, and 256 overrides; reject capacity overflow. Validate reserved fields/flag bits, address width/alignment, duplicate processor APIC IDs, duplicate `(bus, source IRQ)` overrides, and multiple Local APIC Address Overrides. Preserve source bus/IRQ/GSI/flags in the inventory; do not program routes.

An absent ACPI RSDP is reported as unavailable. An advertised but malformed RSDP/root/MADT, an invalid physical range, or a malformed supported MADT entry is a boot-time validation failure; it must not be silently treated as absent. Do not dereference rejected addresses.

## Verification and evidence

- Use independently generated ACPI fixtures (including valid and truncated/corrupt RSDP, root-table, and MADT cases); run parser unit tests for checksum, signature, length, overflow, entry bounds, reserved fields, and invalid address rejection.
- Extend the existing QEMU/OVMF hardening run to require a unique Phase 4.1 success marker and verify that the logged MADT/LAPIC/IOAPIC/override inventory is populated from firmware. Preserve raw serial/QEMU logs, result metadata, command/tool versions, exit status, and hashes using the existing evidence path.
- Keep the existing exception tests and all Fases 0–3.7 CI gates green. Assert that IF remains clear before and after discovery; the QEMU evidence proves only emulated OVMF/TCG behavior, not physical hardware support.
